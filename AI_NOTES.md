# AI Notes

## 1. Which AI Tools Were Used

Claude (Anthropic) was used throughout the development of this project — for architecture design, code generation, and documentation drafting.

## 2. Which Parts of the Code Were AI-Assisted

Every source file in this project (`ExpenseTrackerApplication`, `Expense`, `CreateExpenseRequest`, `ExpenseRepository`, `InMemoryExpenseRepository`, `ExpenseService`, `ExpenseServiceImpl`, `ExpenseNotFoundException`, `GlobalExceptionHandler`, `ExpenseController`, and the test classes) was initially generated by Claude, one file at a time, based on requirements and design decisions I specified explicitly before each file was written — including storage type (in-memory only), field types (`BigDecimal` for amount, `LocalDate` for date), ID generation strategy, HTTP status codes, and exception handling behavior.

I did not let the AI invent requirements or design on its own: each file was scoped by me in advance (interface first, implementation second), and I reviewed the generated code and explanation before approving it and moving to the next file.

## 3. What Was Manually Reviewed or Modified

- I reviewed every generated file's explanation (imports, annotations, methods, line-by-line logic) before approving it, rather than accepting output without reading it.
- I explicitly directed one code change after review: in `InMemoryExpenseRepository.findAll()`, I asked for `List.copyOf(expenses.values())` to be replaced with `new ArrayList<>(expenses.values())` for simplicity — both return a defensive copy, but the latter is more familiar/readable.
- I verified the build configuration (`pom.xml`) dependency-by-dependency and removed one AI-suggested dependency (`spring-boot-starter-validation`) that wasn't strictly required by the assignment, to keep dependencies at the minimum needed.
- I checked the repository/service architecture for consistency — specifically confirming that total-calculation logic stayed in the service layer only, and did not get duplicated into the repository interface, even when a later instruction phrased it ambiguously.
- I flagged a structural conflict between the assignment's example repo layout (`tests/` as a top-level folder) and Maven's standard convention (`src/test/java`), and made an explicit decision to follow Maven convention, documenting the reasoning in the README so it's not hidden from a reviewer.

## 4. AI Suggestions Rejected and Why

- **Bean Validation dependency (`spring-boot-starter-validation`)**: The AI included this by default in an early draft of `pom.xml` as good practice. I rejected it because the assignment does not require input validation, and the instruction was to keep dependencies to the absolute minimum — not to add anything merely because it's idiomatic.
- **`equals()`/`hashCode()`/`toString()` on `Expense`**: The AI noted these are common boilerplate but did not add them, since no assignment feature (comparison, printing, logging) requires them. I confirmed this omission was correct rather than asking for them to be added.
- **A dedicated "total" method on `ExpenseRepository`**: One of my own instructions ambiguously implied the repository should have a total-calculation method. I caught that this would contradict the already-approved architecture (which places total calculation in the service layer) and instructed the AI to keep the repository free of that responsibility, rather than accepting the duplication.
- **Exposing the raw exception message in the global 500 handler**: The AI's first draft of `GlobalExceptionHandler` returned a generic message for unexpected errors rather than the raw exception text, reasoning that leaking internal error details isn't appropriate for a production API. I reviewed and kept this behavior rather than requesting the more verbose (but less safe) alternative.

This document reflects the actual development process for this specific submission: heavy AI assistance in code generation, paired with explicit human-directed scope, review, and at least one direct code correction and one dependency removal. It is not a generic AI-usage disclaimer.
